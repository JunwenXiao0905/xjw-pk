# Sector Observer

面向个人赛道观察笔记的整理与写作技能。目标不是把目录写成券商研报模板，而是帮助用户持续回答：

1. 行业现在走到哪一步；
2. 我该怎么进入这个行业；
3. 哪些玩家、场景和资产值得继续跟踪。

## When to Use

适用于：

- 新建或重组 `赛道观察/行业方向观察/某赛道/`
- 给某个赛道补充行业总览、技术路线、商业化场景、未来预期
- 整理学校、招聘、本地机会、考研路径
- 把公司、政策、招聘、融资、基金持仓等零散材料收敛成稳定文档
- 维护“结论文档 + 证据池”的长期结构

不适用于：

- 只摘录一条新闻且不需要沉淀判断
- 只做单一公司的财务分析
- 只改一个已有段落的措辞而不涉及结构

## Core Rule

先收敛主文档，再堆证据。

赛道笔记默认分成两层：

- `10-41`：稳定结论文档，用来回答问题
- `90-证据池/`：时间敏感材料，用来存证、回溯和支持判断

不要把原始新闻、招聘截图、学校分数和基金短评直接堆进总览文档。

## Default Output Set

默认维护以下文档：

- `10-行业总览.md`
- `11-产业结构与价值链.md`
- `12-技术路线.md`
- `13-商业化场景.md`
- `14-未来预期.md`
- `20-玩家图谱.md`
- `21-成都与本地机会.md`
- `30-考研与进入路径.md`
- `40-投资映射.md`
- `41-观察清单.md`
- `90-证据池/`

各文档职责和边界见 `references/document-roles.md`。

## Workflow

处理一个赛道时，按下面顺序工作：

1. 先看该赛道现有目录和笔记，不要上来新建一堆文件。
2. 判断现有材料属于：
   - 行业判断
   - 技术路线
   - 场景验证
   - 玩家信息
   - 本地机会
   - 考研/进入路径
   - 投资映射
   - 原始证据
3. 先把原始材料放到合适位置，再把结论回写到主文档。
4. 如果多个主题混在同一篇长文里，优先拆职责，不要只在原文末尾追加。
5. 写预测时使用情景或阶段判断，不写绝对口号式结论。
6. 每篇主文档都要能回答“这对用户意味着什么”。

更细的更新规则见 `references/update-workflow.md`。

## Writing Target

文风要求：

- 专业，但不卖弄术语
- 像成熟的个人行业分析，不像卖方研报
- 先讲人话，再引入必要概念
- 每段尽量服务于决策，而不是服务于形式完整

默认读者就是用户本人，因此要持续照顾这三类问题：

- 行业是否值得长期投入
- 成都或周边是否有现实路径
- 读研、就业、投资观察如何彼此映射

## Forecast Rule

对未来预期和投资映射：

- 优先写 `1-2 年` 与 `3-5 年`
- 或写 `基准 / 乐观 / 保守` 三种情景
- 每个判断尽量附：
  - 时间点
  - 依据
  - 置信度
  - 可能失效的条件

不要把“看好某行业”直接写成“看涨某标的”。

## Notes on Players

`20-玩家图谱.md` 不只写公司，也可以写：

- 创新中心
- 实验室
- 研究平台
- 本地高校和研究机构
- 关键零部件和系统集成商

如果一类主体对赛道理解或用户路径有持续意义，就可以进入玩家图谱。
