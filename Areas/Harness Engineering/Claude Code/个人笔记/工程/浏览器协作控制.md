目的是让ai能读取具有登录态的浏览器实例，以便获取更多信息。

# 浏览器协作控制（人 + Agent 共控一个 Edge）


## 1. 核心思路

**人负责登录，Agent 负责读写，两者共享同一个带持久登录态的浏览器实例。**

```
┌──────────┐  扫码登录一次   ┌─────────────────────────────┐
│   人     │ ──────────────▶ │  专用 Edge 实例              │
│          │                 │  --user-data-dir=edge-profile│ ← Cookie/登录态持久保存
│  随时可以 │  肉眼查看/接管   │  --remote-debugging-port=9222│
│  手动操作 │ ◀────────────── │                             │
└──────────┘                 └──────────────┬──────────────┘
                                            │ CDP (HTTP + WebSocket)
                                            │ 127.0.0.1:9222 仅本机
                                     ┌──────▼──────┐
                                     │   Agent     │
                                     │ Node 零依赖  │
                                     │ 打开/读取/  │
                                     │ 翻页/关闭标签│
                                     └─────────────┘
```

分工：
- **人**：双击启动脚本 → 扫码登录 → 之后可以随时切到那个窗口看进度、点验证码、手动翻页（和 Agent 操作不冲突，同一个 DOM）
- **Agent**：通过 CDP 开标签、导航、`Runtime.evaluate` 读渲染后的正文、提取链接、批量抓取落盘

## 2. 为什么不能直接挂载日常浏览器

| 尝试                  | 结果     | 原因                                                                                          |
| ------------------- | ------ | ------------------------------------------------------------------------------------------- |
| 直接连接正在运行的日常 Edge    | ❌      | 日常实例没开调试端口；且 Chromium/Edge **136+ 明确禁止在默认用户目录启用远程调试**（安全策略），加 `--remote-debugging-port` 也没用 |
| Agent 自带内置浏览器       | ❌ 无登录态 | 登录墙内容（BOSS 完整 JD、薪资）看不到                                                                     |
| curl / WebFetch 直接抓 | ❌      | 被 JS challenge / 反爬拦截（返回 0 字节），也拿不到登录态                                                      |
| 无头浏览器 + 账号密码登录      | ❌ 风险高  | 触发风控/验证码，账号可能被限制                                                                            |

结论：**专用 profile + 调试端口的可见 Edge 实例**是唯一同时满足"有登录态、人可介入、Agent 可编程"的方案。

## 3. 一次性搭建：启动脚本

`start-edge-debug.cmd`（⚠️ **必须纯 ASCII**，见踩坑 #1）：

```bat
@echo off
rem Dedicated Edge debug instance for scraping (persistent login profile)
start "" "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --remote-debugging-port=9222 --remote-allow-origins=* --user-data-dir="D:\projects\edge-automation\edge-profile" --no-first-run --no-default-browser-check --start-maximized "https://www.zhipin.com/web/user/?ka=header-login"
echo Edge debug instance started (port 9222, profile: edge-profile)
```

要点：
- `--user-data-dir` 指向**独立目录**（不是默认 profile），这是 136+ 版本允许开调试端口的前提；该目录持久保存 Cookie，**扫码一次，终身受用**（除非 cookie 过期或手动退出登录）
- `--remote-allow-origins=*`：新版 Chromium 会拒绝带未知 Origin 头的 WebSocket 连 CDP，加这个保险
- 与日常 Edge 互不影响、可同时运行（不同 user-data-dir = 不同进程实例）
- 9222 只监听 127.0.0.1，不暴露局域网
- 不加 `--headless` / `--enable-automation`：人要能看到并接管，且不留下自动化指纹（`navigator.webdriver` 为 false）

## 4. CDP 直连核心代码（Node ≥22，零依赖）

CDP 两层接口：
- **HTTP**：`GET /json/version`、`GET /json/list`（列标签页）、`PUT /json/new?url=`（开标签）、`PUT /json/close/<id>`（关标签）→ 都在 `http://127.0.0.1:9222`
- **WebSocket**：每个标签页有独立的 `webSocketDebuggerUrl`（ws://127.0.0.1:9222/devtools/page/<TARGET_ID>），用 `Page.navigate`、`Runtime.evaluate` 等域方法读写页面

最小可用脚本（check / links / scrape 三模式，实战验证过的精简版）：

```js
// cdp-scrape.mjs  —  node cdp-scrape.mjs check | links <url> <out> | scrape <targets.json> <out>
const CDP = "http://127.0.0.1:9222";
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));
const fs = await import("node:fs");

async function newTab(url) {
  // ⚠️ 新版 Chromium 的 /json/new 必须 PUT；url 需 encodeURIComponent 后还原 ://
  const q = "/json/new?" + encodeURIComponent(url).replace(/%2F/g, "/").replace(/%3A/g, ":");
  const res = await fetch(CDP + q, { method: "PUT" });
  if (!res.ok) throw new Error(`HTTP ${res.status} on /json/new`);
  const info = await res.json();
  const ws = new WebSocket(info.webSocketDebuggerUrl);   // Node ≥22 全局 WebSocket
  await new Promise((ok, bad) => { ws.onopen = ok; ws.onerror = () => bad(new Error("ws fail")); });
  let msgId = 0;
  const send = (method, params = {}) => new Promise((resolve, reject) => {
    const id = ++msgId;
    const timer = setTimeout(() => reject(new Error("timeout " + method)), 20000);
    const onMsg = (ev) => {
      try {
        const m = JSON.parse(String(ev.data));           // ⚠️ String(ev.data) 兼容 Blob
        if (m.id === id) {
          ws.removeEventListener("message", onMsg);
          clearTimeout(timer);
          m.error ? reject(new Error(JSON.stringify(m.error))) : resolve(m.result);
        }
      } catch {}
    };
    ws.addEventListener("message", onMsg);
    ws.send(JSON.stringify({ id, method, params }));
  });
  const eval_ = (expression) =>
    send("Runtime.evaluate", { expression, returnByValue: true })
      .then((r) => (r.exceptionDetails ? undefined : r.result?.value));
  return { id: info.id, ws, send, eval: eval_ };
}
const closeTab = (id) => fetch(`${CDP}/json/close/${id}`, { method: "PUT" }).catch(() => {});

// SPA 页面没有可靠的"加载完成"事件 → 轮询正文长度直到稳定
async function pollText(tab, minLen = 200, tries = 6, gapMs = 2500) {
  let text = "", title = "";
  for (let i = 0; i < tries; i++) {
    title = (await tab.eval("document.title")) || "";
    text = (await tab.eval("document.body ? document.body.innerText : ''")) || "";
    if (text.length >= minLen) break;
    await sleep(gapMs);
  }
  return { title, text };
}

const [mode, ...args] = process.argv.slice(2);
if (mode === "check") {
  const list = await (await fetch(CDP + "/json/list")).json();
  for (const t of list.filter((t) => t.type === "page")) console.log(`- ${t.title} :: ${t.url}`);
} else if (mode === "links") {
  const [url, outFile] = args;
  const tab = await newTab(url);
  try {
    await pollText(tab, 3000, 8, 2500);
    const raw = await tab.eval(`JSON.stringify(
      [...new Set([...document.querySelectorAll('a[href*="/job_detail/"]')]
        .map(a => ({href: a.href, text: (a.innerText||'').replace(/\\s+/g,' ').trim()})))]
      .filter(x => x.href && x.text))`);
    fs.writeFileSync(outFile, raw, "utf8");
  } finally { await closeTab(tab.id); tab.ws.close(); }
} else if (mode === "scrape") {
  const [targetsFile, outFile] = args;                 // [{"name":"...","url":"..."}]
  const targets = JSON.parse(fs.readFileSync(targetsFile, "utf8"));
  const tab = await newTab("about:blank");
  const results = [];
  try {
    for (const t of targets) {
      await tab.send("Page.navigate", { url: t.url });
      await sleep(5000);                               // 防风控：页面间隔
      const { title, text } = await pollText(tab, 200, 4, 3000);
      results.push({ name: t.name, url: t.url, title, text });
      fs.writeFileSync(outFile, JSON.stringify(results, null, 2), "utf8"); // 增量落盘
      console.log(`OK: ${t.name} (len=${text.length})`);
      await sleep(3000);
    }
  } finally { await closeTab(tab.id); tab.ws.close(); }
}
setTimeout(() => process.exit(0), 1000);               // ⚠️ 强制退出，避免 ws 残留导致 libuv assertion
```

完整可运行版（含容错/日志）见 `D:\projects\edge-automation\scrape-boss-jobs.mjs`。

## 5. 协作流程（时间线）

```
人：双击 start-edge-debug.cmd ──▶ Edge 弹出，自动打开目标站登录页
人：手机 App 扫码登录（仅首次）──▶ edge-profile 持久保存登录态
      │
Agent：node cdp-scrape.mjs check     确认端口/登录态（看标签页标题）
Agent：node cdp-scrape.mjs links …   抓列表页，提取详情页链接（登录态下比游客多）
Agent：node cdp-scrape.mjs scrape …  逐页导航+读正文，增量落盘 JSON
      │                                （期间人可在该窗口随便看/操作，互不干扰）
Agent：解析 JSON → 结构化 → 每岗一个 md 写入知识库
```

人介入的典型时机：扫码、滑块/验证码、BOSS 偶发的安全验证页。Agent 检测到正文异常（过短/含"安全验证"）就停下来叫人。

## 6. 踩坑清单（全部实际踩过）

1. **cmd 脚本中文乱码**：编辑器存 UTF-8，cmd 按 GBK 解析 → 中文注释变乱指令，连 `msedge`/`--remote-debugging-port` 都被拆碎执行。**批处理文件一律纯 ASCII**（注释用英文）。
2. **`/json/new` 必须 PUT**：老教程里的 GET 会被拒（HTTP 405）。
3. **`ev.data` 可能不是字符串**：Node undici 的 WebSocket 消息可能是 Blob，`JSON.parse(ev.data)` 静默失败会让所有 CDP 响应"超时"。用 `String(ev.data)` 包一层。
4. **进程退出崩溃**：`Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)`——ws 未关就退出。结尾 `setTimeout(() => process.exit(0), 1000)` 强制干净退出。
5. **SPA 加载无准点**：不要依赖 `Page.loadEventFired`（经常错过），按"正文长度阈值 + 轮询重试"判稳。
6. **防风控节奏**：页面间 3-5s 间隔、增量落盘（挂了也不丢已抓的）、不用无头、不加 automation flag。批量抓 35 页零验证码。
7. **登录态抓取差异**：BOSS 游客态只见 20 岗/JD 截断，登录态 34 岗/全量 JD+薪资——**先用登录态抓列表页再展开**，并注意页面"相似职位"推荐区会混入其他公司的岗位链接，**务必在详情页校验公司名**再收录。
8. **纯文本解析比 DOM 快照稳**：CDP 下直接 `document.body.innerText` 拿整页文本，按行 split 找锚点（状态行、标题行、`职位描述`、招聘者活跃行），比维护选择器省事。

## 7. 方案对比

| 方案                                                   | 登录态  | 人可介入    | 依赖           | 适用                                |
| ---------------------------------------------------- | ---- | ------- | ------------ | --------------------------------- |
| **专用 Edge + CDP 直连（本文）**                             | ✅ 持久 | ✅ 同窗口共控 | Node ≥22 零依赖 | 读为主、批量抓取                          |
| chrome-devtools-mcp（见姊妹篇笔记）                          | ✅    | ✅       | npx + MCP    | 已有 Claude Code MCP 体系，要点击/表单/网络面板 |
| Playwright `connectOverCDP("http://127.0.0.1:9222")` | ✅    | ✅       | playwright   | 需要复杂选择器/交互时升级用                    |
| Agent 内置浏览器                                          | ❌    | 弱       | 无            | 无登录需求的公开页面                        |

进阶：交互密集的任务把第 4 节的 `eval` 换成 Playwright 连接同一实例：

```js
import { chromium } from "playwright";
const browser = await chromium.connectOverCDP("http://127.0.0.1:9222");
const page = (await browser.contexts()[0].pages())[0];   // 直接操控现有标签页
await page.click("text=登录");
```

## 8. 安全边界

- 9222 只绑 127.0.0.1，等于"本机任何进程都能操作这个浏览器"——**不要在里面登录网银等高敏感账号**；调试实例只放抓取所需的站点登录态
- 不复制/导出 cookie 到别处，登录态留在 `edge-profile` 目录内
- 抓取节奏克制（本例 35 页 ≈ 7 分钟），尊重站点风控与 ToS，仅用于个人信息收集
