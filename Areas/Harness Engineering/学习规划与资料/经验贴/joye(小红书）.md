# 别再背传统八股了！Agent 开发到底在面什么

时间：2026-04-18 22:57  
来源：小红书经验贴  
说明：根据截图整理，少量被底部浮层遮挡的字句按上下文补齐。

最近在团队接了个新活儿：帮 mt 着筛 Agent 开发实习生的简历，还要做一面。我自己也才大二，突然转换视角坐在面试官的位置上，看完几百份简历后心情真的很复杂，因为大家踩的坑惊人地一致。今天不整那些虚头巴脑的，结合我在这边看到的真实情况，咱们好好盘一盘：面试明明聊得挺嗨，最后到底卡在哪了？

## 1. 开源项目二开的“皇帝的新装”

很多人喜欢拿开源项目包装简历，比如拿港大基于 OpenClaw 二开的 NanoBot 来写。说实话，别骗自己了。你哪怕做了一些魔改、换个高大上的名字，每天看无数份简历的 HR 和懂技术的面试官一眼就能看穿。只要是用过 NanoBot 的人稍微一问，就能发现你根本没有核心的原创逻辑。直接照搬开源，不仅不能证明能力，反而暴露了你缺乏独立思考。开源项目作为简历项目是可以的，但是一定需要有自己的二次开发、独立思考，证明自己的产品和技术架构能力。

## 2. 强行堆砌技术的“缝合怪”

很多人觉得简历上技术栈越多越好。最典型的例子：强行在 NanoBot 上搭一个 RAG，非要搞个“个人私人数据库”。面试官真正看重的是产品思维。我会问你：这个场景真的需要用到 RAG 吗？实际意义大吗？现在市面上现成的替代方案那么多，你非要强行搭一个的逻辑是什么？记住：做项目不是堆 buff，技术是为业务服务的。

## 3. 传统前后端思维还没转过来

如果你面 Agent 岗，简历上还在大篇幅写 JWT 验证、简单的 CRUD，那方向就走偏了。现在是 AI 时代，我们面的是你的架构思维：

- 架构设计：你设计的是单 Agent 还是多 Agent？为什么要用多 Agent，它的核心优势在哪？
- 通信编排：Agent 之间是怎么通信和编排的？
- 工具链：你为你的 Agent 设计了哪些配套工具？如果只停留在“调用 API”，那你的竞争力几乎为零。

## 4. 缺乏对前沿技术的敏锐度

Agent 是一个极速发展的领域，比起死记硬背的传统八股，面试官更看重你的技术嗅觉和选型逻辑。

- LangChain 和 LangGraph 的本质区别是什么？什么是“复杂”，什么是“简单”？
- 你关注过 OpenClaw、Skills、MCP 或者是最近大火的 Hermes Agent 吗？
- 进阶拷问：为什么 Skills 这么受追捧？它对比 MCP 有什么区别？你能解释一下什么是“渐进式披露”吗？如果你一问三不知，说明你只是个代码搬运工，而不是前沿技术的探索者。

## 5. 面试状态与致命的“反问环节”

遇到不会的题，千万不要支支吾吾，更不要“硬装”。我遇到最离谱的是嘴硬，如果你确实能圆过去那我会觉得你临场发挥和表达能力很好，反之我会觉得你这人品行有问题。

- 正确解法：大大方方地说“这道题我不太了解，但基于我的经验，我尝试推导一下……”或者直接要 10 秒钟思考一下。
- 最致命的错误：反问环节是展现积极性的好机会，但我曾遇到候选人只问了一句“面试官你是在国外吗？”（因为我人确实在墨尔本）直接挂掉。连这个项目做什么都不关心，我为什么要你？

反问环节建议问这些：

1. 业务线：项目具体业务是什么？我进来负责哪个模块？团队人数和各自负责的内容？
2. 自我复盘：对比其他人，您觉得我个人技术栈还有哪些遗漏？今天哪里做得好，哪里需要改进？
3. AI 类：公司 / 面试官对于 AI coding 是保持什么态度，有没有一些可以分享的 AI 使用技巧，是否报销 AI 产品（坚决抵制付费实习）。

## 6. 没做过 Eval（评估）

你的 Agent 只是个“玩具”。很多人觉得 Agent 是个“黑盒”（虽然现在用各种 AI SDK 已经能让过程很透明了）。但在真实的业务环境里，实习生进公司就会发现，我们每天会花大量的时间在 Evaluation 上。

如果你在简历上只写了“我搭建了 XX 架构”，我一定会连环追问：

- 为什么选这个架构？是否有更好的选择？
- 你怎么证明这个架构是有效的？
- 你做过量化测试吗？数据在哪里？

建议：你的简历项目无论规模大小，必须写上你是如何做测试和评估的。这也是大家现阶段最应该花时间去打磨的地方。懂 Eval，你才具备了真正的工程化思维，而不是只会在本地跑个 Demo。
