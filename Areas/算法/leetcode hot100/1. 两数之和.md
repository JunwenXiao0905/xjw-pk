# 1. 两数之和

> LeetCode Hot 100 第 1 题 · 哈希表 · 简单
> 这是我们用 **Go** 刷的第一题。代码很短，但里面藏着 Go 最常用的几个语法点（切片、map、range、多返回值），读完后你会对 Go 的"长相"有第一印象。

## 题目描述

给定一个整数数组 `nums` 和一个整数目标值 `target`，请你在该数组中找出 **和为目标值** 的那两个整数，并返回它们的数组下标。

你可以假设每种输入只会对应一个答案，并且你 **不能使用两次相同的元素**。可以按任意顺序返回答案。

### 示例

```text
输入：nums = [2,7,11,15], target = 9
输出：[0,1]
解释：因为 nums[0] + nums[1] == 9 ，返回 [0,1]
```

### 约束

- `2 <= nums.length <= 10^4`
- `-10^9 <= nums[i] <= 10^9`
- `-10^9 <= target <= 10^9`
- **只会存在一个有效答案**

**进阶**：你能想出一个时间复杂度小于 `O(n²)` 的算法吗？

---

## 核心思路

最直白的做法是两层循环枚举所有数对，时间 `O(n²)`。进阶要求我们做得更好。

关键观察：

**我们要找的是 `nums[i] + nums[j] = target`，换个角度看，对于当前遍历到的 `nums[i]`，我需要的是 `target - nums[i]` 这个"搭档"。**

所以问题变成：**每走到一个数，就去查"它的搭档之前出现过没有"。**

"查一个值在不在 / 出现在哪" —— 这正是 **哈希表（map）** 的拿手好戏，查找是 `O(1)`。

一次遍历：

1. 拿到当前数 `v = nums[i]`，算出需要的搭档 `need = target - v`；
2. 去 map 里查 `need`：
   - 在 → 返回 `[搭档的下标, i]`；
   - 不在 → 把当前 `v -> i` 存进 map，留给后面的数当搭档。

一次遍历 `O(n)`，map 查询 `O(1)`，总体 **`O(n)`**。

---

## 一步步写出算法

### 第一步：map 存什么

我们要的是"值 → 下标"，所以 map 的类型是 `map[int]int`：

```go
hash := make(map[int]int) // key=数组里的值, value=它的下标
```

### 第二步：遍历，先查再存

```go
for i, v := range nums {
    need := target - v
    if j, ok := hash[need]; ok {   // 搭档出现过
        return []int{j, i}
    }
    hash[v] = i                    // 把自己留给后面的数
}
```

> **为什么"先查再存"，而不是"先存再查"？**
> 因为题目要求不能使用同一个元素两次。如果先把 `nums[i]` 存进去再查 `need`，当 `need == v` 时（比如 `target=6, nums=[3,...]`）会误判成"自己跟自己配对"。先查，保证查到的搭档一定在当前元素**之前**，天然不会撞自己。

### 第三步：兜底返回

题目保证有唯一解，理论走不到这里，但 Go 要求函数有返回值：

```go
return nil
```

---

## 代码实现（Go）✅ 推荐写法

```go
func twoSum(nums []int, target int) []int {
    hash := make(map[int]int) // 值 -> 下标

    for i, v := range nums {
        need := target - v
        if j, ok := hash[need]; ok { // ok=true 表示 need 在 map 里
            return []int{j, i}
        }
        hash[v] = i
    }

    return nil // 题目保证有解,这里走不到
}
```
 
### 复杂度分析

- **时间**：`O(n)`，只遍历一次，每次 map 操作均摊 `O(1)`。
- **空间**：`O(n)`，最坏情况下 map 存了几乎所有元素。

---

## 暴力解法（对比用）

```go
func twoSum(nums []int, target int) []int {
    for i := 0; i < len(nums); i++ {
        for j := i + 1; j < len(nums); j++ {
            if nums[i]+nums[j] == target {
                return []int{i, j}
            }
        }
    }
    return nil
}
```

- **时间** `O(n²)`，**空间** `O(1)`。
- 数据量 `n ≤ 10^4` 时 `O(n²)` ≈ `10^8`，会超时；面试直接给哈希表解法。

## 手动模拟一遍（哈希表解法）

用 `nums = [2,7,11,15], target = 9`：

| 第几轮 | `v=nums[i]` | `need=9-v` | map 里查 `need` | 动作 | map 变成 |
|---|---|---|---|---|---|
| i=0 | 2 | 7 | 不在 | 存 `2->0` | `{2:0}` |
| i=1 | 7 | 2 | **在(下标0)** | 返回 `[0,1]` | — |

结果 `[0,1]` ✅

## Go 语法点拨（重点，对应你的《Go 基础与工程》）

这道题代码只有 8 行，但每一行都是 Go 高频语法。逐一对应你的笔记章节：

### 1. `[]int` —— 切片（对应笔记 3.1）

`nums []int` 是**切片**，不是数组。Go 里函数参数几乎不用固定长度数组，都用切片。

- 返回 `[]int{j, i}` 是一个**字面量切片**，等价于先 `make` 再赋值。
- 你之前 TS 写的是 `number[]`，Go 的 `[]int` 是它最接近的对应物，但底层是「指针+len+cap」三字段 header（你笔记 3.1.2 画过那个图）。

### 2. `map[int]int` —— Go 的哈希表（笔记第 3 章续，待补）

这是你 Go 笔记里 **还没写到** 的类型，正好这题第一次用，先给个速览：

```go
m := make(map[int]int)   // 创建,必须 make(或字面量 map[int]int{})
m[key] = value           // 写
v := m[key]              // 读:不存在时拿到零值(int 的零值是 0)
v, ok := m[key]          // 读 + 存在性:ok=false 表示 key 不在
delete(m, key)           // 删
len(m)                   // 元素个数
```

**和 TS/Python map 最大的区别**：Go 取一个不存在的 key **不会报错**，而是返回**值类型的零值**。所以你**不能**用 `if m[key] != 0` 来判断"在不在"（万一它存的本来就是 0 呢？）——必须用**逗号 ok 模式**（comma ok idiom）：

```go
if j, ok := hash[need]; ok {
    // ok 是 bool,这才是"key 存在"的可靠判据
}
```

> 这就是为什么代码里写 `if j, ok := hash[need]; ok` 而不是 `if hash[need] != 0`。这是 Go 判 map/类型断言"是否存在"的标准姿势，也是这题最容易写错的地方。

### 3. `for i, v := range nums` —— 遍历（对应笔记 2.4）

等价于 TS 的 `nums.forEach((v, i) => ...)` 或 `for (const [i, v] of nums.entries())`，但注意 **Go 的 range 返回顺序是 `(下标, 值)`**，i 在前、v 在后（TS 很多地方值在前）。

- 只要下标：`for i := range nums`
- 只要值：`for _, v := range nums`（`_` 是空白标识符，丢弃）
- **坑**（你笔记 2.4 提过）：`v` 是元素的**副本**，改 `v` 不影响原切片。这题只读不改，没事。

### 4. 多返回值 + `if` 初始化语句（对应笔记 2.4 / 2.5）

```go
if j, ok := hash[need]; ok {  // if 可以带一条初始化语句
```

这一行干了三件事：

1. `j, ok := hash[need]` —— 接住 map 的两个返回值（值 + 是否存在）；
2. `; ok` —— 判断条件；
3. `j` 和 `ok` 的**作用域仅限这个 if 语句**（含 else 分支），出了 if 就访问不到。这是 Go 控制"变量作用域最小化"的惯用写法。

### 5. `make` —— 给引用类型分配（对应笔记 3.1.4）

`map` 和 `slice` 一样是引用类型，零值是 `nil`。**`var m map[int]int` 之后直接 `m[k]=v` 会 panic**（nil map 不能写），必须 `make` 初始化才能用。这跟 slice 的 `var s []int; s=append(s,1)` 行为不一样，是个经典坑——后续学到 map 章节会重点讲。

### 6. 函数签名（对应笔记 2.5）

```go
func twoSum(nums []int, target int) []int
```

- 参数：`nums []int, target int`，相邻参数同类型时**前面的类型可省**，只在最后写一次。注意这跟 `nums []int, target int` 里的 `[]int` —— `[]int` 是切片类型，`target` 是 `int`，类型不同所以都得写。
- 返回值写在参数列表后面的 `) []int` 里。Go 是**静态类型**，返回类型必须显式声明，不像 TS 靠推断。

---

## 易错点

### 1. 判 map 是否存在，必须用 comma ok

```go
// ❌ 错:nums 里可能有 0,或者 need 没存过时零值也是 0
if hash[need] != 0 { ... }

// ✅ 对
if j, ok := hash[need]; ok { ... }
```

### 2. 先查再存，别先存再查

否则 `target = 2*v`（搭档等于自己）时会用同一个元素两次。

### 3. `return nil` 合法

`[]int` 是切片，切片的零值是 `nil`，所以 `return nil` 是合法的（返回一个 nil 切片）。如果返回类型是定长数组 `[2]int` 就不能 `return nil` 了——这也是为什么函数用切片不用数组。

---

## 一句话总结

**一次遍历 + 一个 `map[值]下标`，每走到一个数就查它的搭档在不在；判存在用 `v, ok := m[k]`，存之前先查以防撞自己。**

这道题记三件事就够：

1. `map[int]int` 怎么创建（`make`）、怎么读写；
2. **comma ok 模式**判存在性（Go 判 map 的标准姿势）；
3. `for i, v := range` 的 `i, v` 顺序，以及 `if` 带初始化语句的作用域。
