# 49. 字母异位词分组

> LeetCode Hot 100 第 2 题 · 哈希表 · 中等
> 上一题练了 `map[int]int`。这题会接触 map 的进阶用法——**value 是切片**（`map[string][]string`），以及 Go 字符串/排序的核心 API。读完你会对"map 怎么当分组容器用"有扎实手感。

## 题目描述

给你一个字符串数组 `strs`，请你将 **字母异位词** 组合在一起。可以按任意顺序返回结果列表。

**字母异位词**：由相同字母重新排列得到的字符串（包括相同字符串本身）。

### 示例

```text
输入：strs = ["eat", "tea", "tan", "ate", "nat", "bat"]
输出：[["bat"],["nat","tan"],["ate","eat","tea"]]
```

解释：三组分别是 `bat` / `nat,tan` / `ate,eat,tea`（注意同一组内顺序不限）。

### 约束

- `1 <= strs.length <= 10^4`
- `0 <= strs[i].length <= 100`
- `strs[i]` 仅包含小写英文字母

---

## 核心思路

"字母异位词"的本质是：**字母组成完全相同（种类 + 数量），只是排列顺序不同**。

所以问题归约为：**给每个字符串找一个"标识"，让所有字母异位词的标识相同。**

这个"标识"在哈希表里叫 **key**。同一个 key 下的所有字符串就是一组。

于是算法分两步：

1. **遍历每个字符串**，算出它的 key；
2. **以 key 为 map 的键，把原字符串塞进对应分组**；最后把 map 的所有 value 收集起来。

剩下的核心问题是：**这个 key 怎么选？** 两种主流做法：

- **做法一：排序后的字符串当 key** —— `"eat"`/`"tea"`/`"ate"` 排完序都是 `"aet"`。
- **做法二：字母计数当 key** —— 统计每个字母出现次数，拼成定长签名。

两种都是 `O(n · k log k)` vs `O(n · k)`（n=字符串数，k=最长串长度），但做法一在 Go 里代码短得多，是首选。

---

## 一步步写出算法（做法一：排序当 key）

### 第一步：map 的结构怎么定

我们要"key → 一组原字符串"，所以 value 是**字符串切片**：

```go
groups := make(map[string][]string)
```

这是 Go map 的进阶用法，先记住几个要点（后面专门讲）：

- value 是 `[]string`，意味着每个 key 对应一个切片，切片里存同组的原始字符串。
- `groups[key]` 在 key 不存在时返回 **nil 切片**（`[]string` 的零值），`append` 到 nil 切片是**安全的**（会自动建切片）——这点跟 map 本身的 nil 不同。

### 第二步：怎么给字符串排序

Go 里字符串是**不可变**的（UTF-8 字节序列，笔记 2.2 提过），**不能直接对 string 排序**。标准套路是：先转成字节切片 `[]byte`，排序，再转回 string：

```go
b := []byte(s)        // string → []byte (可改)
slices.Sort(b)        // 原地升序排(Go 1.21+ 的 slices 包,泛型排序)
key := string(b)      // []byte → string
```

> ⚠ **坑**：`sort` 包**没有** `sort.Bytes` 函数！老的 `sort` 包只有 `sort.Ints`/`sort.Strings`/`sort.Float64s`，对 `[]byte` 没有便捷函数。Go 1.21+ 用泛型 `slices.Sort` 一步到位（`slices.Sort` 能排任何可比较类型，`byte`/`uint8` 是整数，符合约束）。Go 1.21 之前只能用 `sort.Slice(b, func(i,j int) bool { return b[i] < b[j] })`。现代代码直接 `slices.Sort`。

### 第三步：分组

```go
for _, s := range strs {
    b := []byte(s)
    sort.Bytes(b)
    key := string(b)

    groups[key] = append(groups[key], s)   // 把原串塞进对应组
}
```

这一行 `groups[key] = append(groups[key], s)` 是 Go map + slice 的**核心惯用法**，拆开看（下一节细讲）。

### 第四步：把 map 的 value 收集成结果

题目要返回 `[][]string`（一组一组的），所以遍历 map 把所有 value 收集起来：

```go
result := make([][]string, 0, len(groups))
for _, g := range groups {
    result = append(result, g)
}
return result
```

> `make([][]string, 0, len(groups))` —— 还记得吗？第一个 `0` 是 len（从空开始），第二个是 cap（预分配，避免反复扩容）。这是上轮讲 make 坑的正解写法。

## 代码实现（Go）✅ 推荐写法

```go
import "slices"

func groupAnagrams(strs []string) [][]string {
    groups := make(map[string][]string)

    for _, s := range strs {
        b := []byte(s)
        slices.Sort(b)            // 排序字节,作为 key
        key := string(b)

        groups[key] = append(groups[key], s)
    }

    // 收集所有分组
    result := make([][]string, 0, len(groups))
    for _, g := range groups {
        result = append(result, g)
    }
    return result
}
```

### 复杂度分析

- **时间**：`O(n · k log k)`
  - n 个字符串，每个串排序是 `O(k log k)`（k 是串长）。
  - 总体 `O(n · k log k)`。
- **复杂度记忆**：`slices.Sort` 底层是 introsort（快排 + 堆排序），平均/最坏都是 `O(n log n)`（这里 n 指被排序序列的长度 k）。
- **空间**：`O(n · k)`，存所有字符串。

## 做法二：字母计数当 key（更快，但代码长）

因为题目保证**只有小写字母**（只有 26 种），可以用一个长度 26 的计数数组当 key。两种 key 的选择：

1. **拼成字符串** `"1#0#0#...#2#"`（每个字母出现次数用分隔符连起来）。
2. **用 `[26]int 数组直接做 key** —— Go 1.21+ 的 map 支持可比较的数组类型做 key（数组是值类型且可比较）。

后者代码更优雅（Go 1.21+ 推荐）：

```go
func groupAnagrams(strs []string) [][]string {
    groups := make(map[[26]int][]string)   // 数组直接做 key!

    for _, s := range strs {
        var cnt [26]int
        for _, ch := range s {
            cnt[ch-'a']++                  // 统计字母频次
        }
        groups[cnt] = append(groups[cnt], s)   // cnt 数组当 key
    }

    result := make([][]string, 0, len(groups))
    for _, g := range groups {
        result = append(result, g)
    }
    return result
}
```

- **时间**：`O(n · k)`（每个串只扫一遍统计，不排序）—— 比做法一快。
- **关键点**：**Go 的 map key 必须是"可比较"的类型**。`[26]int` 这种定长数组是值类型且可比较（能用 `==`），所以能做 key；但切片 `[]int` 不行（切片不可比较）。这是个 Go 重要知识点，下面专门讲。

> **`ch - 'a'`**：`ch` 是 `rune`（int32），`'a'` 也是 rune，相减得到 0~25 的偏移，正好做数组下标。这是处理英文字母的经典技巧，后端做字符统计也常用。

两种做法时间复杂度对比：

| 做法 | key 怎么来 | 单串耗时 | 总体 |
|---|---|---|---|
| 排序当 key | `sort.Bytes([]byte(s))` | `O(k log k)` | `O(n·k log k)` |
| 字母计数当 key | 遍历统计 `[26]int` | `O(k)` | `O(n·k)` |

面试时**推荐讲做法一**（好懂、代码短），再补一句"如果追求 `O(n·k)` 可以用计数签名"。工程里小写字母场景做法二更快。

## 手动模拟一遍（做法一）

用 `strs = ["eat", "tea", "tan", "ate", "nat", "bat"]`：

| 原串 | 排序后 key | 动作 | groups 状态 |
|---|---|---|---|
| `"eat"` | `"aet"` | 新 key,建组塞 `eat` | `{"aet":["eat"]}` |
| `"tea"` | `"aet"` | 同 key,追加 `tea` | `{"aet":["eat","tea"]}` |
| `"tan"` | `"ant"` | 新 key | `{"aet":[...], "ant":["tan"]}` |
| `"ate"` | `"aet"` | 同 key,追加 `ate` | `{"aet":["eat","tea","ate"], ...}` |
| `"nat"` | `"ant"` | 同 key,追加 `nat` | `{"ant":["tan","nat"]}` |
| `"bat"` | `"abt"` | 新 key | `{"abt":["bat"]}` |

最后收集 map 的所有 value → `[["eat","tea","ate"], ["tan","nat"], ["bat"]]`（顺序不限）✅

## Go 语法点拨（重点）

### 1. `map[string][]string` —— value 是切片（笔记第3章续，待补）

这是这题最重要的新结构。分两层理解：

**外层是 map**：`map[string]...`，key 是 string，查找 O(1)。
**内层是切片**：`...[]string`，每个 key 对应一个字符串切片。

```go
groups := make(map[string][]string)

groups["aet"] = []string{"eat"}               // 给 key 显式赋一个切片
groups["aet"] = append(groups["aet"], "tea")  // 往这个切片 append
```

**核心惯用法（必须吃透）**：

```go
groups[key] = append(groups[key], s)
```

这一行干的事：右边 `groups[key]` 取出当前 key 的切片（不存在时是 nil），`append` 追加 `s`，再**整体写回** `groups[key]`。必须写回，因为 append 可能换底层数组（笔记 3.1.7 讲过 "append 必须接回 s"）。

**为什么这里 map 的值能用 nil 切片 append，而 map 本身 nil 不能写？**

- `var m map[string][]string; m["x"] = ...` → **panic**（nil map 不能写）。
- `m := make(...); append(m["x"], "y")` → **安全**。`m["x"]` 在 key 不存在时返回 nil 切片，`append(nil切片, "y")` 是合法的，会建一个新切片。

这两个 nil 行为不同，是 Go 最容易踩的坑之一。**口诀：nil map 不能写，nil slice 能 append。**

### 2. 字符串 ↔ 字节切片互转

```go
s := "eat"
b := []byte(s)     // string → []byte,拷贝出可改的字节
b[0] = 'E'         // 可以改 b,不影响 s(string 不可变)
s2 := string(b)    // []byte → string
```

- Go 的 string 是**不可变**的（对比 TS/Python 的字符串也是不可变，这点一样）。
- 要改字符串内容，标准套路是 `[]byte(s)` 拷贝一份可改的版本。
- `[]byte(s)` 和 `string(b)` 都会产生**拷贝**（不是共享底层），所以频繁转会有性能开销。性能敏感场景可以用 `unsafe`（后端进阶再说）。

> **`byte` = `uint8`**，`rune` = `int32`（笔记 2.2）。处理 ASCII 用 `[]byte`，处理中文等多字节字符用 `[]rune`（因为一个汉字是 3 字节 UTF-8，`[]byte` 会把汉字拆散）。本题保证纯小写字母，用 `[]byte` 最合适。

### 3. `slices.Sort` —— 切片排序（笔记第9章续，待补）

Go 1.21+ 推荐用 **`slices` 包**（泛型），一个 `slices.Sort` 函数搞定所有可比较类型：

```go
slices.Sort(b)        // 排 []byte,原地升序
slices.Sort(ints)     // 排 []int
slices.Sort(strs)     // 排 []string
slices.Sort(floats)   // 排 []float64
```

对比老的 `sort` 包：

| | `sort` 包（老） | `slices` 包（Go 1.21+，推荐） |
|---|---|---|
| 内置类型 | `sort.Ints`/`sort.Strings`/`sort.Float64s`（每个类型一个函数） | `slices.Sort` 一个泛型函数全包 |
| `[]byte` | ❌ **没有** `sort.Bytes`，必须自定义比较 | ✅ `slices.Sort(b)` 直接用 |
| 自定义比较 | `sort.Slice(s, less)` | `slices.SortFunc(s, less)` |
| 降序 | `sort.Sort(sort.Reverse(...))`（繁琐） | `slices.Sort(s); slices.Reverse(s)` |

特点：

- **原地排序**，不返回新切片（直接改参数），所以不用接回。
- 默认**升序**。
- **底层是 introsort**（快排 + 堆排序），平均/最坏都是 `O(n log n)`，且**不稳定**（相同元素相对顺序可能变）——字母异位词分组不在意组内顺序，所以无所谓。要稳定排序用 `slices.SortStable`。

> **坑提醒**：`sort` 包**没有** `sort.Bytes` 函数（只有 Ints/Strings/Float64s）。Go 1.21+ 排 `[]byte` 直接用 `slices.Sort(b)`。

### 4. map 的遍历 + 收集 value

```go
for _, g := range groups {
    result = append(result, g)
}
```

- `range map` 返回 `(key, value)`，这里只用 value（key 是排序后的串，不要），所以 `_` 丢弃 key。
- **map 遍历顺序随机**（笔记 2.4 提过）——所以输出分组的顺序、组内元素的顺序都不固定。题目说"任意顺序"，所以无所谓。

### 5. `ch - 'a'` —— rune 运算（做法二用到）

```go
for _, ch := range s {     // ch 是 rune
    cnt[ch-'a']++
}
```

- `for _, ch := range s` 遍历字符串时，`range` 按 **rune** 切分（笔记 2.4 提过），`ch` 是 `int32`/`rune`。
- `'a'` 是字符字面量，类型也是 `rune`（值 97）。
- `ch - 'a'`：`'c' - 'a'` = `99 - 97` = 2，正好把 'a'~'z' 映射到 0~25 做下标。这是处理英文字母的经典技巧，记住。

### 6. 数组能做 map key，切片不能（笔记第3章续，待补）

做法二用了 `map[[26]int][]string`，这里有个 Go 重要规则：

> **map 的 key 必须是"可比较"类型（comparable）**——即能用 `==` 判断相等。

- **能做 key**：基本类型、string、数组（定长，如 `[26]int`）、指针、struct（字段都可比）、接口。
- **不能做 key**：切片 `[]T`、map、函数——它们**不可比较**（用 `==` 会编译错）。

为什么切片/map 不能比较？因为它们是**引用类型**，比"相等"语义模糊（是比内容还是比指针？Go 选择不支持，避免歧义）。所以：

```go
map[[]int]int      // ❌ 编译错:invalid map key type
map[[3]int]int     // ✅ OK:定长数组是值类型,可比较
```

这是 Go 类型系统的一个重要边界，记住"切片/map/func 不能做 key"就够了。

## 易错点

### 1. `groups[key] = append(groups[key], s)` 必须整体写回

```go
// ❌ 错:没写回,append 结果丢了
append(groups[key], s)

// ✅ 对
groups[key] = append(groups[key], s)
```

原因：`append` 可能换底层数组，新切片 header 不写回 map，map 里存的还是旧的（没追加成功的）切片。这跟"append 必须接回 s"是同一个坑。

### 2. nil map 不能直接写

```go
var groups map[string][]string
groups["aet"] = []string{"eat"}   // ❌ panic: assignment to entry in nil map

groups := make(map[string][]string)   // ✅ 必须 make 初始化
groups["aet"] = []string{"eat"}
```

map 是引用类型，零值 nil 的 map **不能写**（读返回零值但安全）。用之前必须 `make`。这点和 nil slice 能 append 形成对比，是高频坑。

### 3. 不能直接对 string 排序

```go
slices.Sort(s)   // ❌ s 是 string,不是 []byte,编译错

// ✅ 转 []byte 排
b := []byte(s)
slices.Sort(b)
key := string(b)
```

记住：**string 不可变，要改先转 `[]byte`**。

### 4. key 选择要保证"字母异位词 → 相同 key"的映射成立

- 排序法：同一组字母排完序必然相同 ✅
- 计数法：`[26]int` 数组相等 ⟺ 字母组成相同 ✅
- **错误示例**：用"字符串长度"当 key —— 不行，长度相同未必是异位词（`"abc"` 和 `"def"` 都长度 3）。

## 一句话总结

**字母异位词分组的本质是"找统一标识"**：把每个字符串排序（或统计字母频次）当 key，原串塞进 `map[key][]string` 对应分组，最后收集 value。Go 里核心惯用法是 `groups[key] = append(groups[key], s)`——map value 是切片时，取出→追加→写回，三步缺一不可。

这题记四件事：

1. **`map[K][]V`（map 的 value 是切片）** 是 Go 分组/分桶的标准结构；
2. **`groups[key] = append(groups[key], x)`** 是 map + slice 的核心写回惯用法；
3. **string 不可变，改之前先转 `[]byte`**；`sort.Bytes` 原地排序不接回；
4. **map 的 key 必须可比较**——数组 `[N]T` 可以，切片/map/func 不行。
